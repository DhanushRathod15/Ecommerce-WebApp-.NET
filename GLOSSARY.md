# Glossary of Terms

Quick reference guide for technical terms used throughout the documentation.

## Architecture & Design Patterns

### Clean Architecture
An architectural pattern that separates concerns into layers with clear dependency rules. Dependencies point inward, with business logic at the center and infrastructure at the edges.

### Microservices
An architectural style where an application is composed of small, independent services that communicate over network protocols. Each service is focused on a specific business capability.

### Domain-Driven Design (DDD)
A software development approach that focuses on modeling software to match the business domain. Key concepts include entities, aggregates, value objects, and bounded contexts.

### CQRS (Command Query Responsibility Segregation)
A pattern that separates read operations (queries) from write operations (commands), allowing each to be optimized independently.

### Event-Driven Architecture
A software architecture paradigm where systems communicate through events. When something happens (an event), other systems react to it.

### Repository Pattern
A design pattern that provides an abstraction layer between the data access layer and business logic, making data access code more maintainable and testable.

### Unit of Work Pattern
A pattern that maintains a list of objects affected by a business transaction and coordinates writing out changes and resolving concurrency problems.

## .NET Concepts

### ASP.NET Core
A cross-platform, high-performance framework for building modern, cloud-based, internet-connected applications.

### Entity Framework Core (EF Core)
An object-relational mapper (ORM) that enables .NET developers to work with databases using .NET objects, eliminating the need for most data-access code.

### MediatR
A simple mediator pattern implementation in .NET. Used to implement CQRS by sending commands and queries through a mediator.

### Middleware
Software components assembled into an application pipeline to handle requests and responses. Examples: authentication, error handling, logging.

### Dependency Injection (DI)
A design pattern where objects receive their dependencies from external sources rather than creating them. Built into ASP.NET Core.

### Async/Await
C# keywords for asynchronous programming, allowing code to run without blocking the thread, improving application responsiveness and scalability.

## Database Concepts

### ORM (Object-Relational Mapping)
A programming technique that converts data between incompatible type systems (relational databases and object-oriented programming languages).

### Migration
A version-controlled way to incrementally update database schema to keep it in sync with the application's data model.

### DbContext
The primary class in Entity Framework Core for interacting with a database. Represents a session with the database.

### Connection String
A string that specifies information about a data source and how to connect to it (server address, database name, credentials).

### Index
A database structure that improves the speed of data retrieval operations on a table at the cost of additional writes and storage space.

## Docker & Containerization

### Docker
A platform for developing, shipping, and running applications in containers. Containers package software with all dependencies.

### Container
A lightweight, standalone, executable package that includes everything needed to run an application: code, runtime, tools, libraries, and settings.

### Docker Image
A read-only template with instructions for creating a Docker container. Built from a Dockerfile.

### Dockerfile
A text file that contains instructions for building a Docker image.

### Docker Compose
A tool for defining and running multi-container Docker applications using a YAML file.

### Multi-stage Build
A Dockerfile technique that uses multiple FROM statements to create smaller, more secure final images by separating build and runtime environments.

### Volume
A Docker feature for persisting data generated by and used by Docker containers. Data persists even after container removal.

## Kubernetes Concepts

### Kubernetes (K8s)
An open-source container orchestration platform for automating deployment, scaling, and management of containerized applications.

### Pod
The smallest deployable unit in Kubernetes. A pod contains one or more containers that share storage and network resources.

### Deployment
A Kubernetes resource that provides declarative updates for pods and replica sets, managing application rollouts and rollbacks.

### Service
A Kubernetes abstraction that defines a logical set of pods and a policy for accessing them (load balancing, service discovery).

### Ingress
A Kubernetes resource that manages external access to services, typically HTTP/HTTPS routing.

### ConfigMap
A Kubernetes object used to store non-confidential configuration data in key-value pairs.

### Secret
A Kubernetes object that stores sensitive information like passwords, tokens, and keys.

## API & Web Concepts

### REST (Representational State Transfer)
An architectural style for designing networked applications using HTTP requests to access and manipulate data.

### API Gateway
A server that acts as a single entry point for multiple microservices, handling routing, composition, and protocol translation.

### YARP (Yet Another Reverse Proxy)
A Microsoft library for building reverse proxy servers in .NET, commonly used for API gateways.

### JWT (JSON Web Token)
A compact, URL-safe token format for securely transmitting information between parties as a JSON object.

### Swagger/OpenAPI
A specification for describing REST APIs. Swagger UI provides interactive API documentation.

### CORS (Cross-Origin Resource Sharing)
A mechanism that allows resources on a web server to be requested from another domain outside the domain from which the resource originated.

### Rate Limiting
A technique to control the amount of incoming requests to an API to prevent abuse and ensure fair usage.

## Testing Concepts

### Unit Test
A test that verifies the behavior of a small, isolated piece of code (a unit), typically a single method or function.

### Integration Test
A test that verifies that different parts of the system work correctly together.

### Mock
A simulated object that mimics the behavior of real objects in controlled ways, used in testing to isolate the code being tested.

### Test Fixture
A fixed state of a set of objects used as a baseline for running tests, ensuring tests run in a known environment.

### Code Coverage
A measure of how much of your code is executed during automated testing, typically expressed as a percentage.

### Test-Driven Development (TDD)
A software development approach where tests are written before the code that needs to be tested.

## CI/CD Concepts

### CI (Continuous Integration)
A practice where developers frequently merge code changes into a central repository, followed by automated builds and tests.

### CD (Continuous Deployment/Delivery)
The practice of automatically deploying code changes to production (Continuous Deployment) or to a staging environment (Continuous Delivery).

### Pipeline
An automated workflow that takes code from version control through build, test, and deployment stages.

### Artifact
A file or set of files produced by a build process, such as compiled binaries, container images, or deployment packages.

### Build Agent
A machine or container that executes build and deployment tasks in a CI/CD pipeline.

## Cloud & Azure Concepts

### Azure Container Apps
An Azure service for running containerized applications without managing infrastructure.

### Azure Kubernetes Service (AKS)
Microsoft's managed Kubernetes service for deploying and managing containerized applications.

### Azure Container Registry (ACR)
A managed Docker registry service for storing and managing container images.

### App Service
An Azure service for hosting web applications, REST APIs, and mobile backends.

### Resource Group
A logical container for Azure resources that share the same lifecycle, permissions, and policies.

## Monitoring & Observability

### Application Insights
An Azure service for monitoring live applications, detecting performance anomalies, and diagnosing issues.

### Telemetry
Automatic measurement and data collection from remote or inaccessible points for monitoring and analysis.

### Structured Logging
A logging approach where log entries are written in a structured format (like JSON) making them easier to query and analyze.

### Health Check
An endpoint or mechanism that reports the health status of an application and its dependencies.

### Metrics
Numerical measurements collected over time that provide insights into application behavior and performance.

### Distributed Tracing
A method for tracking requests as they flow through distributed systems, helping identify performance bottlenecks.

## Security Concepts

### Authentication
The process of verifying who a user is (login).

### Authorization
The process of verifying what a user is allowed to do (permissions).

### OAuth 2.0
An authorization framework that enables applications to obtain limited access to user accounts.

### OpenID Connect
An identity layer built on top of OAuth 2.0 for authentication.

### TLS/SSL
Cryptographic protocols for securing communications over computer networks.

### Certificate
A digital document that proves the ownership of a public key, used for secure communications.

## Performance & Scalability

### Caching
Storing frequently accessed data in a fast-access location (like memory) to improve performance.

### Redis
An in-memory data structure store used as a database, cache, and message broker.

### Load Balancing
Distributing network traffic across multiple servers to ensure no single server is overwhelmed.

### Horizontal Scaling
Adding more machines to handle increased load (scaling out).

### Vertical Scaling
Adding more resources (CPU, RAM) to existing machines (scaling up).

### Circuit Breaker
A design pattern that prevents an application from repeatedly trying to execute an operation that's likely to fail.

### Retry Policy
A strategy for automatically retrying failed operations with delays and limits.

## Message & Event Systems

### Message Queue
A form of asynchronous service-to-service communication where messages are stored in a queue until processed.

### RabbitMQ
An open-source message broker that implements the Advanced Message Queuing Protocol (AMQP).

### Azure Service Bus
A fully managed enterprise message broker with message queues and publish-subscribe topics.

### Event Bus
A mechanism that allows different parts of an application to communicate through events.

### Pub/Sub (Publish/Subscribe)
A messaging pattern where senders (publishers) don't send messages directly to receivers (subscribers), but through a message broker.

## Development Tools

### NuGet
The package manager for .NET, used to create, share, and consume .NET libraries.

### Git
A distributed version control system for tracking changes in source code during development.

### Visual Studio
Microsoft's integrated development environment (IDE) for developing applications on Windows.

### VS Code
A lightweight, cross-platform code editor with extensive extension support.

### Postman
A platform for API development and testing with a graphical interface for making HTTP requests.
